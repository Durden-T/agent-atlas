# Outcome

建立 Agent Atlas：一个使用 TypeScript、在本机浏览器运行的个人 GitHub agent 资源库。用户点击收集后，应用搜索公开仓库、读取证据并使用真实 Jev 分类，帮助用户找到并整理工具、工作流、技能及相关设施；用户通过仓库链接自行查看具体内容。

# Scope

- 用户明确选择“分类仍全部限定使用 Jev”。相关性和全部标签继续使用真实 Jev，不测试或接入其他分类模型；保留 15 个标签及全部失败记录；按用户后续授权降低标签阈值、升级 Jev 1.14，并按最新澄清收窄业务搜索与记忆检索的边界。

- 使用 agent、harness、skill、claude、codex 五组独立关键词按 Star 降序搜索，以及相关作者或组织的公开仓库扩展发现；按查询预算保存实际来源，将新增与积压候选合并后按 Star 降序处理。
- 统一以 GitHub 仓库为资源单位，合集与普通仓库使用相同的收集和分类流程；展示仓库链接，供用户自行查看其中内容。
- 分类证据只读取仓库简介、主题和 README；README 不存在直接过滤；README 正文为空或仅空白且简介为空或仅空白、主题列表为空时也由程序直接过滤。保存原因并遵守复查间隔，不调用 Jev、不补读其他文件。
- 用真实 OpenRouter Jev 判断相关性，并按资源形态、任务用途、agent 能力三组共 15 个标签分类，允许多标签；两个指定合集仅用于分类设计参考，由程序根据返回概率推导待复核，不向 Jev 提供“证据不足”或“不确定”候选项。
- 提供中文资源列表、搜索筛选、详情与原文证据、待判断与待复核视图、个人保留或忽略操作，以及收集任务进度与用量。
- 所有数据保存在本地 SQLite。主界面提供“本轮 Jev 处理上限（仓库数）”，默认 100、可设 -1 或 1–1000 并持久保存；-1 不设本轮判断名额上限。只计实际发起的仓库请求，成功、无关、待复核或失败都占额，缓存和过滤不占额，剩余仓库保留在队列。发现请求预算默认40，同样支持 -1 或 1–1000；-1 不设本轮搜索与作者扩展请求次数上限，README与Jev不计入发现预算。任务时限、取消、分页保存与候选读取保护仍有效。
- 收集与查看都支持最小 Star 和最近更新天数，初始值为至少 100 个 Star、最近 180 天有推送。默认复查间隔为 -1，已扫描的正例与未收录反例均不复查；间隔和收集门槛等通过界面配置并持久保存。
- 只由点击按钮启动网络收集或分类；没有定时任务或启动时自动调用。

- 增加可创建、重命名、删除的收藏夹，一个项目可属于多个收藏夹；列表和详情显示归属并支持本地筛选。
- 打开本机详情时自动标记已查看，用户可手动切换；查看状态和收藏夹归属独立持久保存，后续扫描不覆盖。

# Non-goals

- 不保证发现 GitHub 上所有相关项目，不把预算内结果标记成全量扫描。
- 不部署服务器、不制作桌面安装包、不增加多人账号系统。
- 不替用户安装、执行或自动更新发现的工具或技能，不更改 GitHub 的收藏状态。
- 不抓取私有仓库，不引入另一个生成式模型来替代 Jev 或生成未经来源支持的说明。
- 不增加向量数据库、聊天助手、通知推送或定时后台采集。
- 不同步、导入或持续分析用户的 GitHub Star 列表；已完成的 Star 研究只用于理解需求。
- 不固定采集两个参考合集，不展开合集链接，不拆分仓库内技能、工作流或插件，也不建立合集条目与独立资源的对应或去重关系。
- 不检查许可证；本需求中的“开源”指 GitHub 公开仓库，不以许可证是否存在或类型限制收录。
- 不设置适用生态分类或筛选；具体宿主与兼容信息由用户查看仓库原文。

# Acceptance examples

- A1: 从独立仓库按说明启动后，本机浏览器能打开中文界面；刷新或重启后，已保存的资源、人工整理结果和任务记录仍然存在。
- A2: 页面加载、刷新以及应用启动均不触发 GitHub 或 Jev 网络请求；只有用户点击收集、继续处理或明确重新判断才会启动相关请求。
- A3: 收集使用 agent、harness、skill、claude、codex 五组独立关键词，GitHub 搜索统一按 Star 降序，保留分页与作者扩展来源。新增和积压候选去重后按 Star 降序、同 Star 按仓库 ID 升序处理；各入口判断前执行 Star 和推送时间门槛。合集按普通仓库处理，不读取个人 Star 或展开合集链接；不宣称全 GitHub 的全局排名。
- A4: 仓库搜索超过单次结果上限时分段处理；预算、超时或不完整返回阻止完成时，明确显示部分完成及未覆盖查询。分页与查询参数保存后可在下一次手动运行续跑，不反复只读第一页。
- A5: 后端通过 JEV_OPENROUTER_KEY 调用真实 OpenRouter Decisions 接口，每个需判断的仓库一个请求，包含 1 个相关性及 15 个标签判断，共 16 个独立问题（相关性与知识学习两个Noul、其余14个二选一Choice），最多并发 2 个仓库，使用完整规格中的英文提示模板。Jev 输入仅含名称、描述、主题、单个 readme 对象及英文规则，标签定义仅在对应问题中出现一次；不含仓库 ID、主语言、Star 或时间。README 不存在直接过滤，读取错误单独报告，不补读其他文件或付费判断“证据是否充分”。保存实际模型、证据版本和原始判断，前端响应、日志和受版本管理文件不包含密钥。
- A6: 同一仓库可在资源形态、任务用途、agent 能力三组拥有多个标签，每组 5 个、共 15 个，覆盖完整规格中的精简分类；技能、办公协作和记忆检索不会混为单一互斥类别，普通软件不会仅因可被 agent 使用就自动收录为相关。合集可以归为合集与资料，内部条目不形成独立资源。
- A7: 无关、低确定性的待复核和模型错误分别可见；错误不会变成分类成功，不会静默切换模型，也不会为了得到通过结果重复判断。公开仓库不因许可证缺失或类型进入待复核或被排除。
- A8: 列表直接展示仓库名称与链接、原文描述、Star 数、最近推送时间和分类标签，支持按 Star 与最近推送时间排序。筛选可按名称或描述、最小 Star、最近更新天数、三组分类、归档状态和判断状态组合使用；查看条件只作用于本地记录并独立保存，默认 100 个 Star、180 天，空结果与加载失败有明确反馈。
- A9: 详情页展示可点击的 GitHub 仓库链接、发现来源、README 原文证据及读取时间、更新时间与判断记录；仓库自述、模型分类与人工决定能够区分，用户可自行进入 GitHub 查看合集或技能内容。
- A10: 用户可保留、忽略或修正仓库标签；后续收集不会覆盖人工决定，也不调用 GitHub 写接口。
- A11: 主界面可修改并保存本轮 Jev 处理上限，默认 100、接受 -1 或 1–1000；-1 不设判断名额上限，正数达到实际发起请求的仓库上限就停止调用，过滤或缓存不占额，失败占额。发现请求预算默认40，同样支持 -1 或 1–1000；-1 不设搜索与作者扩展请求次数上限，两个预算互不替代，0非法。任务时限与取消仍有效。任务保存配置并显示发现或更新数、过滤数及原因、间隔跳过数、完成判断数、待判断数、待复核数、未收录数、失败数和实际用量；重复点击不并发启动第二个任务，取消保留成功结果，重启标为中断，继续由用户点击。
- A12: 收集门槛、查看条件、判断上限、请求预算与复查间隔可配置并持久保存。已完成扫描的正例、未收录反例及无 README 过滤记录均按稳定 ID 复用：默认 -1 永不复查，0 每次允许检查，X 天内跳过。允许复查但内容未变时不改写内容或调用 Jev，仅排序元数据变化不重判；影响判断的证据改变才重判。明确重新判断使用现有证据，失败与未完成不能冒充已扫描反例。
- A13: 未配置 Jev 密钥、GitHub 认证失效、限流、网络超时及非法外部返回均产生可操作的错误；默认只监听本机，仓库内容不能指示服务执行命令或访问任意 URL。
- A14: 核心发现、仓库去重、证据版本、分类解释、缓存、人工覆盖和任务生命周期通过自动测试；类型检查与生产构建通过，并完成浏览器检查。既有真实 GitHub/Jev 记录证明接口接线，真实历史低概率结果通过当前代码回放验证复核机制。按用户最新决定停止准确率优化、评分和新增付费验证，准确率不作为交付门槛；保留当前 atlas-38 分类实现及全部旧预标、原始结果和失败记录，不宣称达到旧准确率标准，隔离样例保持未调用。

- A15: 用户能创建、重命名、删除收藏夹，为项目加入或移除多个收藏夹，列表及详情显示所有归属，按收藏夹筛选；重启后保存，删除收藏夹不删除项目，扫描和分类不覆盖个人收藏。
- A16: 成功打开本机详情，或列表项目显示过后随向下滚动完全离开视口顶部，自动标记已查看；未曾可见、被筛选或翻页隐藏本身不标记。列表与详情显示已查看或未查看，能手动切换并按状态筛选，未查看筛选排除保存成功的已查看项目；轮询与刷新不重新覆盖手动未查看决定，重启后保存，不触发外部请求。

# Constraints and invariants

- 所有应用代码使用 TypeScript；前端与服务端共用明确的数据契约，业务判断独立于界面与传输层。
- API 密钥仅由服务端环境读取。研究阶段使用 Python 技能脚本不构成应用对 Python 的运行依赖。
- 公共仓库内容作为不可信证据处理；Jev 只给出有界判断，不负责获取事实、授权操作或生成任意说明。
- 用稳定 GitHub 仓库 ID 归并同一仓库的重复搜索结果；入库、缓存、判断与人工操作使用同一仓库身份，不比较合集条目与独立资源，不按名称或内容相似度合并不同仓库。
- SQLite 位于本机 `~/Library/Application Support/Agent Atlas/atlas.sqlite`，存储资源、未收录扫描记录、证据、判断、人工决定、配置与任务进度；密钥不入库。查看使用采集时的快照，更新时间筛选依据 `pushed_at`。
- 缺失成本显示未知，不填成零；概率和 confidence 不表示实际准确率。研究试验阈值只作为可调整的复核起点。
- 所有外部调用、分页、扩展深度、任务时间和结果数量有界；已完成记录使用事务保存，成功部分不因其他记录失败而丢失。
- 当前工作仅属于 /Users/cyqu/scripts/agent-atlas；不修改父仓库的既有工作。

# Decisions

- 用户已确认：在 /Users/cyqu/scripts/agent-atlas 新建独立 Git 仓库。
- 用户已确认：本机浏览器网页、个人使用。
- 用户已确认：只在点击收集按钮时运行，不启用每日或其他定时收集。

- 研究读取了 15 个代表性仓库的 README，并对其中 12 个进行了真实 Jev 试验：3 次请求、48 个判断项，29 项达到试验阈值、19 项待复核；试验采用旧版互斥主分类，不构成准确率基准，也不代替最终三组多标签方案的验证。
- 用户已澄清：hesreallyhim/awesome-claude-code 和 ComposioHQ/awesome-claude-skills 仅供分类设计参考，不是应用必须采集的来源。本次研究已读取两者 README、贡献说明及实际目录，并读取前者的分类配置与结构化资源表。
- 分类研究事实：前者的 config.yaml 定义 23 个一级类、8 个二级类，资源表有 252 行；后者 README 的 Skills 下有 10 类任务用途及一个应用自动化分组，其 composio-skills 目录有 833 个目录条目。这些是来源快照计数，不是已收录、已分类或已验证可用的资源数量。
- 分类精简为三组可组合筛选：它是什么、用来做什么、为 agent 提供什么能力，每组 5 个、共 15 个标签。用户已移除适用生态分类；完整标签与判断边界以完整规格为准，两个合集只作设计参考，应用根据目标仓库自身证据判断。
- 用户已明确：合集与普通仓库同样处理，用户自行进入仓库查看内容；不拆分合集或内部技能、工作流、插件，不展开合集链接，也不做合集条目与独立资源的对应和去重。
- 用户已确认：收集和查看默认至少 100 个 Star、最近 180 天更新；默认复查间隔 -1。门槛和间隔都是可修改的持久配置，扫描过而未收录的反例同样受间隔约束，不能每次重新付费判断。
- 请求方案：每仓库一次 Jev 请求，包含相关性及知识学习两个Noul和其余14个独立标签Choice问题；相关性使用 Noul 判断是否相关，不再区分直接与辅助；标签仍二值：知识学习使用Noul，其余14个使用Choice，不再另问分类状态。共享规则和仓库正文发送一次，标签定义不重复发送；最多并发 2 个仓库。
- 处理顺序：五组关键词统一按 Star 降序搜索，本轮已发现与积压候选合并后按 Star 降序处理。Jev 上限是实际发起请求的仓库数，主页面可修改，默认 100；发现请求预算独立控制。
- 用户已确认：只读仓库简介、主题和 README，不自动补扫其他文件。README 不存在直接过滤，属于有过滤原因的成功检查，不冒充模型反例；仅当 README 正文为空或仅空白、简介为空或仅空白且无主题时由程序过滤为“无有效分类证据”，不调用 Jev；其他简短或空 README 仍按现有元数据判断，低确定性由程序标为待复核。
- 用户要求 Jev 提示使用英文，界面仍为中文。Star 研究帮助理解资源范围，应用不持续读取个人收藏；搜索按用户最新决定只保留 agent、harness、skill、claude、codex，不增加 llm、mcp 或其他细分关键词、主题与特征文件搜索。
- 用户已澄清：“开源”在本需求中指 GitHub 公开仓库，不检查许可证，不设许可证筛选或许可相关待复核状态。
- 分解预检结论：保持一个 Native 变更。发现、证据、分类、人工覆盖与界面共同依赖资源身份和任务状态契约，当前拆成独立子变更的协调成本高于收益。
- 普通实现选择：React 界面、Node.js 服务、SQLite 本地存储；具体库沿用最小依赖方案，在 Build 中核实兼容性。
- 代码结构设计：单个 TypeScript 项目按 collection、catalog、judgment 三个业务模块组织；统一收集入口和仓库处理流程，纯规则与 HTTP、SQLite、界面实现分离。测试通过模块接口使用真实临时 SQLite 与可替换的外部 HTTP、时钟；具体职责与失败契约见完整规格，不增加独立包、外部队列或标签变更机制。
- 界面设计提案：使用白底蓝灰的三栏资料台与连续仓库列表，三组标签逐行并列；收集参数与查看筛选分开。窄屏使用可收起筛选和独立详情，具体颜色与字号见规格。
- 用户已确认完整简报、规格、界面与代码结构设计，授权进入 Build 实现与验证；保持现有 15 个标签，不实现标签变更机制。
- 用户已确认的分类约束：沿用 atlas-2 的 15 个标签与五处判断边界，移除全部 Jev 问题中的 insufficient_evidence，不设置不确定候选。相关性改为 Noul，只判断是否相关，试验阈值为 ≥0.8 相关、≤0.2 无关、中间待复核；当时标签使用二选一Choice；原0.8 阈值由用户后续授权降低，当时实现采用 0.65 / 0.15，并保留旧记录。用户指定的 Comet、LoopX、Trellis、Prismantis 作为相关正例补充验证；旧预标和失败记录保持原样。
