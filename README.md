# Agent Atlas

本机运行的 GitHub agent 工具、工作流与技能资源库。TypeScript、React、Node.js 原生 HTTP 与 SQLite；通过 Jev Decisions 分类。启动和浏览只访问本地数据，只有点击操作才访问 GitHub 或 Jev。

## 启动

需要 Node.js 24.20.0 或更新版本。先在启动终端配置 `JEV_OPENROUTER_KEY`，再执行：

```sh
npm ci
npm run build
npm start
```

打开 <http://localhost:4317>。GitHub 凭据使用 `GITHUB_TOKEN` / `GH_TOKEN`，或 `gh auth login --hostname github.com` 保存的本地登录。密钥只由后端读取，不会保存到配置文件或浏览器。Jev 调用产生实际费用。

开发时 `npm run dev` 会先构建界面并观察后端文件；修改前端后重新执行构建以更新浏览器静态文件。

也可使用项目内的 mise 任务：

```sh
mise tasks                 # 查看全部任务
mise run install           # 安装依赖
mise run dev               # 开发运行
mise run start             # 构建后启动
mise run verify            # 类型、自动测试、格式、生产构建
mise run test:browser      # 本机浏览器回归
mise run test:live --run   # 真实 GitHub/Jev，付费请求最多100次
```

`test:live` 必须显式传 `--run`；恢复已有验证时再传 `--resume` 和实际证据目录。`verify` 不包含浏览器或付费测试。任务复用现有 npm 命令，使用当前 Node.js 环境。

可选环境配置：

| 配置                  | 默认值                                                   |
| --------------------- | -------------------------------------------------------- |
| `PORT`                | `4317`，仅绑定 `127.0.0.1`                               |
| `ATLAS_DATABASE_PATH` | `~/Library/Application Support/Agent Atlas/atlas.sqlite` |
| `JEV_OPENROUTER_KEY`  | 必须提供实际密钥才能开始收集                             |

## 使用

收集默认最小 100 Star、最近 180 天推送、复查间隔 -1、本轮最多 100 次 Jev 请求、40 个发现请求。这些参数均可修改并保存。查看条件独立作用于本地快照，也可保存。

Jev上限和发现请求预算均支持 `-1` 或 `1–1000`，`-1` 表示不设置对应次数上限，0无效。发现预算只计GitHub搜索与作者分页请求及重试，每页最多100个候选，不含README读取或Jev调用；Jev上限只计实际发起的分类请求。流程先发现再判断，发现数不占Jev名额；发现最多使用前7.5分钟，为读取和分类保留后半时限，未完成分页留待下次收集。发现阶段显示已发起的GitHub请求数。两项不限次数时仍可取消，并保留现有15分钟任务时限、最多5000候选读取保护和未完成队列。

- **开始收集**：发现并保存候选，然后按已发现候选的 Star 降序判断；超预算的发现分页保留至下一次收集。
- **继续待判断**：处理已有候选；不发起新的发现搜索。
- **明确重试失败请求**：允许再次提交可能已经付费的失败请求。普通收集不会自动重放。

Jev 限流时停止新的派发，保存成功结果与未处理队列，显示部分完成；费用缺失显示未知。

- **重新判断**：仅使用当前已保存的 README，绕过缓存与复查间隔，产生独立付费调用。
- **收藏夹**：在查看条件中创建、改名或删除；在详情中把项目加入多个收藏夹。列表展示全部归属，可按收藏夹筛选。删除收藏夹保留项目和判断记录。
- **已查看**：成功打开本机详情，或列表项目显示过后随向下滚动完全离开视口顶部，自动标记；从未显示、被筛选或翻页隐藏本身不标记。“未查看”筛选排除已保存为已查看的项目，可在详情中手动切换。轮询与刷新不会覆盖手动决定。
- **保留、忽略、修正标签**：只保存本机人工决定，后续收集不会覆盖。

复查间隔 -1 表示已完成扫描永不复查，0 表示每次允许复查，正整数表示间隔天数。已收录、未收录、待复核和证据过滤记录均适用。读取失败与未完成不会冒充成功扫描；门槛过滤也不属于模型反例。README 缺失直接过滤；README 正文和简介都为空或仅空白、主题为空时也直接过滤，不调用 Jev。其他空或简短 README 仍与元数据一起判断。

仅 GitHub 读取失败时，恢复读取后相同证据继续复用成功分类，即使选择了“明确重试失败请求”。只有实际发起的 Jev 请求失败或结果未知才按付费重试处理。队列处理仓库前重新读取最新本地状态，手动重判已经完成的结果会按复查间隔和缓存复用，避免重复派发。

每个仓库一个 Jev 请求，含相关性与知识学习两个Noul及其余14个标签Choice，共16项；README 发送一次，15个标签均使用完整正反定义，每个候选描述包含definition和政策example，不增加候选或问题。当前规则 `atlas-38`，相关性只控制收录，各标签仍依自己的定义判断；固定模型 `typesafe/jev-1.14`，禁用模型回退。相关性 ≥0.8 为相关、≤0.2 为无关；15个标签共用门槛T=0.52：Choice胜出概率≥T时确认；知识学习Noul的p≥T肯定、p≤1-T（0.48）否定，中间待复核。Noul只展示实际p，不生成confidence；Choice差值只作原始展示。这是复核策略，不表示两种原语已同等校准。其余由程序保留待复核，不向模型提供不确定选项，不合成概率。15 个界面标签不变；少量正反政策示例不作为仓库事实，不增加判断题或文档。知识源连接器的搜索/读取操作可构成检索，业务技能中的职位搜索与简历导入不构成记忆与检索。编码流程的 PRD、技术规格和实施计划归开发与办公，不单独构成内容用途；普通代码成果检查不构成 agent 评测；显示 agent 运行或完成状态、工具调用事件与状态属于执行观测。自有外部应用集成包括明确的读取、拉取和导入。知识整理是独立用途，不要求教学；普通产品用法或让agent执行其它任务的指令本身不构成学习用途。完整真实分类验收完成情况见验证记录。

搜索仅覆盖 GitHub 已返回且保存的候选。按 Star 排序不代表全 GitHub 排名；部分完成会列出未覆盖查询。个人 Star 和参考合集仅用于设计研究，应用不会同步个人 Star、展开合集链接或拆分内部技能。

日期和Star分段使用单个范围限定符，避免重复同名条件使GitHub区间失效。修正后的发现队列独立版本化，旧任务记录与已收录仓库保留。README的JSON接口响应在2MiB传输界限内验证编码；GitHub对大文件返回encoding=none时，按同一SHA读取原始blob，取最多48KiB正文前缀后取消下载，不读取其他仓库文件。超长正文按完整字符截断；发给Jev的原始证据总量仍最多48KiB，保存截断标记，不生成摘要。

## 验证

```sh
npm run check
npm test
npm run build
# 已安装 agent-browser 时可运行本机浏览器回归
npm run test:browser
```

测试通过真实临时 SQLite 和可控 HTTP 边界验证；测试替身不作为真实 Jev 质量证明。`tests/live/gold*.json` 与 `results-*.json` 分别保存各轮固定输入、调用前预标、实际模型、请求和返回；空 README 明确标记为合成契约样例。旧轮次存在不确定标签与预标错误，不能当作全标签验证通过，也不代表全 GitHub 的准确率或召回率。详见 [验证记录](docs/validation.md)。

浏览器回归包含实际点击收集、继续及重试的14个任务场景：无关及各类待确认结果不重复判断、预算、间隔、缓存、失败恢复、显式重判、证据变化与服务重启。使用独立浏览器会话、临时文件数据库和受控 GitHub/Jev 接口，不读取实际密钥或写入个人资源库；原有收藏夹、滚动已查看、手机布局和任务分页回归一并运行。

真实上游端到端检查使用生产构建、独立应用进程和独立数据库，需要实际 GitHub 凭据及 `JEV_OPENROUTER_KEY`，会产生费用，只有显式运行下列命令才会调用。累计付费请求最多100次；中途失败可用 `--resume <输出目录>` 从保留数据库继续，不重做首次分类。证据保存在 `.comet/live-e2e/`，包含数据库、原始判断、任务、用量和截图。默认自动检查不运行这个脚本。

```sh
npm run build
node scripts/live-e2e.ts --run
```

按用户决定，停止准确率优化、评分及新增付费准确率验证，准确率不作为交付门槛；真实上游端到端验证另经授权，只验证流程与持久化。保留当前 `atlas-38`，尚未验证的新提案不启用。旧准确率标准没有通过，全部失败与原始记录保留，隔离样例不再调用。`scripts/validate-results.ts` 保留为旧标准的只读历史评分工具，不属于当前交付检查；复核机制仍用真实历史低概率记录验证。

`node scripts/validate-live.ts --check` 默认选择当前规则的预标文件，只离线校验预标、证据哈希及规则版本。真实验证使用 `--run --gold <固定预标路径> --output <新的结果路径>`；已有结果路径会拒绝重放，防止重复付费或覆盖原始结果。自动测试不会发起真实 Jev 请求。

同一数据库只允许一个应用进程，重复启动会明确报错。数据为本机 SQLite；退出保留已成功结果，未完成任务标为中断。重启后需要手动继续。复制数据库备份前先正常停止应用，或使用支持 SQLite WAL 的备份工具。
